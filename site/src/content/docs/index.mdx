## What Polyvec is

Agents should be able to query a company's entire knowledge base constantly —
thousands of reads per day per agent — at negligible cost. Existing vector
databases optimize for the general case; Polyvec optimizes for one workload:
**massive, cheap, high-recall reads over company knowledge**.

It is the future knowledge layer of [Polygrow](https://github.com/SRogDev/Polygrow).
It is not a general-purpose Pinecone/Qdrant replacement, and it is not a
memory layer (episodic/conversational memory stays separate).

## Honest scope

- **Pre-release (v0.x).** The engine is real and tested (244 workspace
  tests), but there are no tagged releases yet — see
  [Limitations & roadmap](/project/limitations/).
- Retrieval-quality numbers in [Performance](/operations/performance/)
  measure pipeline mechanics with a stub embedding provider (a hash
  function), not semantic search quality. No cross-system comparisons are
  published.
- The server binds **localhost only by default**; auth is opt-in. Read
  [Security](/operations/security/) before exposing it.
